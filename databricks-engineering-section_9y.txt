Explain Metric Views versus Materialized Views
----------------------------------------------

For the exam, the simplest way to think about it is:

Metric View = "What is the metric?"
Materialized View = "Precompute the result."

The exam guide explicitly calls out both together in the Section 9 objective and also uses them together in Sample Question 10.

Metric Views

A Unity Catalog Metric View provides a single governed definition of a business metric that can be reused consistently across reports and dashboards.

Business problem it solves

Imagine different teams calculate:

Net Revenue = Revenue - Discounts

But each dashboard implements the calculation slightly differently.

Result:

Dashboard A says £1.2M
Dashboard B says £1.15M
Dashboard C says £1.18M

Nobody trusts the numbers.

A Metric View solves this by defining Net Revenue once and allowing everyone to reuse the same governed definition.

Exam clue words

If the question mentions:

authoritative definition
single source of truth
governed metric
reusable metric
consistent KPI
business definition

Think:

✅ Metric View

Materialized Views

A Materialized View stores a pre-computed result so users do not need to recompute expensive joins and aggregations every time they run a query.

Business problem it solves

Suppose a dashboard calculates:

SQL
Sales by Region by Month

using:

a 5-billion-row fact table
multiple joins
large aggregations

Without precomputation:

every dashboard query repeats the work
performance suffers

A Materialized View stores the aggregate result and refreshes it, allowing dashboards to read the precomputed data instead.

Exam clue words

If the question mentions:

faster dashboards
pre-computed aggregates
expensive joins
expensive aggregations
query performance
dashboard latency

Think:

✅ Materialized View

Side-by-Side Comparison
Question	Metric View				Materialized View
Purpose		Define a metric				Precompute results
Focus		Governance and consistency		Performance
Solves		Different teams calculating KPIs 
		differently				Slow queries
Typical phrase	"Single definition of Net Revenue"	"Dashboard aggregation is slow"
Stores business meaning?	
		Yes					No
Improves query speed?	
		Not its primary purpose			Yes


The Favourite Exam Scenario

This is almost exactly the pattern used in the guide's Sample Question 10.

Problem:

Every dashboard calculates Net Revenue differently.
Dashboards are slow because they recompute joins and aggregations.

Best answer:

✅ Define Net Revenue in a Metric View
✅ Store the expensive pre-computed aggregates in a Materialized View

Exam Memory Trick

When reading a question, ask:

"Are they worried about the meaning of the number, or the speed of calculating it?"

Meaning of the number → Metric View
Speed of the calculation → Materialized View
Both problems → Metric View + Materialized View ✅

That distinction is the key takeaway from Section 9.
